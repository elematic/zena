# Zena 0.0.2-preview.1

2026-11-19

## Notable changes

### The first preview

This is the first release of Zena, a statically typed language that compiles to WebAssembly GC. It is a preview: the language, the standard library and the tools will change, and a release before 1.0 can break code that compiled with the one before.

The release is the `zena` command for macOS (Apple Silicon), Linux (x86_64 and ARM64) and Windows (x86_64). It has the compiler, the standard library, the formatter, the linter, the test runner, the documentation extractor, the language server and the package manager built in. The VS Code extension is released with it.

## Packages

### zena-lang:compiler 0.0.2-preview.1

#### Added

- Self-hosted Zena compiler targeting WebAssembly GC and the Component Model (`zena-component`, `component`, `core`, `js`, and `zena-js` targets) with the ZIR backend.
- The compiler reads `zena-lock.json` at `lockfileVersion` 1 (`LOCKFILE_VERSION`), and refuses another version, or none.
- A workspace package's `name` gives its scope, `"name": "zena-lang:markdown"`, and its key in the workspace is that name.

### cli 0.0.2-preview.1

#### Added

- Standalone `zena` command bundling the CLI module and standard library for macOS (Apple Silicon), Linux (x86_64 and ARM64), and Windows (x86_64).
- Commands for compiling (`build`), running (`run`), testing (`test`), formatting (`fmt`), linting (`lint`), API documentation (`doc`), benchmarking (`bench`), language server (`lsp`), precompiling (`precompile`), and package management (`pkg`).
- Programs that `zena run` and `zena-run` start can put the terminal in raw mode and read keys as they are pressed (`zena:host/terminal`), which `zena-lang:terminal`'s prompts do. The terminal is put back when the program ends, however it ends.
- `zena pkg add`, `zena pkg update` and `zena pkg fetch` print their steps down a line on the left of the terminal, in color, with a spinner while they wait on the network. Warnings (`▲`) and errors (`■`) go to stderr.
- `zena pkg add` without a version takes a package's latest stable release, or its latest pre-release when it has no stable one, and says so. When it can add nothing, it says whether the package has no releases or every release is retracted.
- `zena-lock.json` records `"lockfileVersion": 1`, the version of its format, and `zena` reads only that version. A lockfile of a newer version asks for a newer `zena`.
- `zena pkg login <handle or DID>` signs in with atproto OAuth, in the browser. The registry's sign-in page hands the answer back to `zena`; with `--no-browser`, or where there is no browser to open, as over SSH, it shows a line to paste into the terminal. `BROWSER` names the command that opens the address. An app password also signs in, from `--password-stdin` or `ZENA_APP_PASSWORD`.
- `zena pkg logout` revokes an OAuth session at the PDS.
- When an OAuth session has ended, after two weeks or once revoked, the commands that act as you say to sign in again with `zena pkg login`.
- `zena pkg publish` publishes a path dependency with the range its entry gives in `version`, and refuses a range that leaves out the version at the path. Without one it publishes `^` that version.
- `zena pkg init --scope acme` writes `"name": "acme:<name>"`, and `zena pkg publish --scope` writes the scope into the name.
