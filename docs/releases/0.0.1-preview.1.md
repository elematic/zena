# Zena 0.0.1-preview.1

2026-11-18

## Packages

### compiler 0.0.1-preview.1

#### Added

- Self-hosted Zena compiler targeting WebAssembly GC and the Component Model (`zena-component`, `component`, `core`, `js`, and `zena-js` targets) with the ZIR backend.

#### Changed

- **Breaking:** The compiler's package is `compiler`, in `packages/compiler`: imports read `'compiler/parser'`, where they read `'zena-compiler/parser'`.
- The compiler reads `zena-lock.json` only at `lockfileVersion` 1 (`LOCKFILE_VERSION`), and refuses another version, or none.
- A workspace package's `name` gives its scope, `"name": "zena-lang:markdown"`, and its key in the workspace is that name.

#### Removed

- **Breaking:** `{x: y}` field renaming in record and class destructuring patterns; use `{x as y}` instead (`:` in a pattern introduces a nested sub-pattern).
- **Breaking:** the `scope` field of `zena-package.json`, and a workspace root's scope for its packages.

### cli 0.0.1-preview.1

#### Added

- Standalone `zena` command bundling the CLI module and standard library for macOS (Apple Silicon), Linux (x86_64 and ARM64), and Windows (x86_64).
- Commands for compiling (`build`), running (`run`), testing (`test`), formatting (`fmt`), linting (`lint`), API documentation (`doc`), benchmarking (`bench`), language server (`lsp`), precompiling (`precompile`), and package management (`pkg`).
- Programs that `zena run` and `zena-run` start can put the terminal in raw mode and read keys as they are pressed (`zena:host/terminal`), which `zena-lang:terminal`'s prompts do. The terminal is put back when the program ends, however it ends.

#### Changed

- `zena --version` names the compiler `compiler`, its package's new name, where it said `zena-compiler`.
- `zena pkg add`, `zena pkg update` and `zena pkg fetch` print their steps down a line on the left of the terminal, in color, with a spinner while they wait on the network. Warnings (`▲`) and errors (`■`) go to stderr, without the `warning:` and `Error:` prefixes.
- `zena pkg add` without a version takes a package's latest pre-release when it has no stable release, and says so. When it can add nothing, it says whether the package has no releases or every release is retracted.
- `zena-lock.json` records `"lockfileVersion": 1`, the version of its format, and `zena` reads only that version. Delete a lockfile an earlier `zena` wrote, which has no `lockfileVersion`, and run `zena pkg update` to write it again; a lockfile of a newer version asks for a newer `zena`.
- `zena pkg publish` publishes a path dependency with the range its entry gives in `version`, and refuses a range that leaves out the version at the path. Without one it publishes `^` that version, as before.
- `zena pkg init --scope acme` writes `"name": "acme:<name>"`, and `zena pkg publish --scope` writes the scope into the name, where both wrote a `scope` field.

#### Removed

- **Breaking:** `zena pkg publish` and the other `zena pkg` commands no longer take a package's scope from the workspace root's manifest.

### zena-lang:terminal 0.0.1-preview.1

#### Added

- `terminal/colors`, `terminal/layout` and `terminal/animation`, which were `zebra/colors`, `zebra/layout` and `zebra/animation`.
- `terminal/prompts`: prompts that the user answers with the keyboard (`text`, `password`, `confirm`, `select` and `multiselect`), which throw `PromptCancelled` on Escape or Ctrl+C and `PromptUnavailable` where there is no terminal.
- `terminal/keys`: the keys a terminal in raw mode sends (`KeyDecoder`), read from stdin by `TerminalKeys`, or given in advance by `ScriptedKeys` for tests.
- `isTerminalStdin` in `terminal/colors`.
- `terminal/output`: `Output`, which prints a command's progress on the rail, with a spinner while it waits.

### zena-lang:markdown 0.0.1-preview.1

#### Added

### atproto 0.0.1-preview.1

#### Added

- AT Protocol data model, DAG-CBOR, CIDs, repository Merkle Search Trees and proofs, DID and handle resolution, XRPC, and service authentication.
- `atproto/oauth`: signing in with atproto OAuth as a public client. `startAuthorization` pushes the authorization request with PKCE and a DPoP key made for the session, `finishAuthorization` trades the code for tokens, and `OAuthSession` signs every request to the PDS, follows the servers' nonces, refreshes its token when the PDS says it is no longer valid, revokes it, and is kept as JSON.
- `atproto/dpop`: DPoP (RFC 9449) keys, ES256 proofs and their verification, and JWK thumbprints.
- `XrpcClient.signer`, a `RequestSigner` that authorizes each request on its own and can have it sent again.
- `AccountSession`, which `Session` and `OAuthSession` implement, and which `getServiceAuth` takes.

### package-manager 0.0.1-preview.1

#### Added

- Package manifest and workspace readers, source archives, registry client methods, dependency version resolution, lockfiles, and package cache fetching.
- `testing/fake-oauth`: an authorization server for the fake PDS, which signs in with OAuth without a browser. The fake PDS takes DPoP-bound tokens for `getServiceAuth` and `putRecord`, as far as their scope allows.
- A dependency on a package on disk can give the range it is published with beside its path, `{"path": "../semver", "version": "~0.0.3"}`. `Manifest.pathRanges` holds the ranges, `publishedRange` gives the range a release states for a path dependency, and `writeDependencies` keeps a range the file has.

#### Changed

- Lockfiles record `lockfileVersion` (`LOCKFILE_VERSION`, 1), and `readPins` refuses another version, or none.
- A manifest's `name` gives the package's scope before its name, `"name": "acme:router"`, and `Manifest.scope` reads it from there.
- `writeDid` writes a scope it is given into `name`.

#### Removed

- **Breaking:** the `scope` field of `zena-package.json`, and a workspace root's scope for its packages. Give each package's scope in its own name.
