## Fixes made

Each has a ledger entry dated 2026-10-31: the edit hook and pre-push check
(format, lint on changed lines, commit tags, private words), `watch-prs`,
the stacked-PR procedure and the rules from memory in AGENTS.md, and an
AGENTS.md example that no longer contradicts the lint rules.

## Proposed, waiting for a decision

- The dev VM's Bash tool shell: zsh's `nomatch` and word-splitting cause
  most failed Bash calls. Run the tool with bash, or `unsetopt nomatch` in
  the non-interactive zsh setup.
- Load direnv in non-interactive shells on the dev VM, so commands need no
  `eval "$(direnv export bash)"` prefix.
- Sessions start in `/home/dev/work`, so this repository's
  `.claude/settings.json` and skills don't load; enter the session's
  worktree with Claude Code's EnterWorktree tool instead of `cd`, or run
  the repository's hooks from a user-level hook (README, "Hooks").
- GitHub stacked PRs (`gh stack`), generally available since 2026-10-06,
  for the restack after a squash merge.
- A cleanup PR running `zena lint --fix` over the existing findings, then
  lint in CI.
- AGENTS.md's "Reading and Editing Files" rule says never to read or edit
  with shell commands; the harness's own guidance says the opposite, and
  agents followed the harness (13,230 Bash calls to 762 reads with the
  file tool).
